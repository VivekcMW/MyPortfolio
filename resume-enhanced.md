#### **Design Systems Architecture — Multi-Domain, Multi-Scale**
[→ View detailed case study](https://uxvivek.netlify.app/work/design-systems-scale)

*Personal ownership: System architecture, domain modeling, token naming, accessibility compliance, Figma documentation, team education*

- **Strategic System Design:** Architected a 6-domain design system (OOH, Data Science, AI, FinTech, Design Engineering, Consumer) with 6 composable color palettes (Dark, Light, High Contrast, Warm, Cool, Sepia). Each domain has semantic-named tokens, design rationale, and accessibility targets (WCAG AA baseline, WCAG AAA for OOH and High Contrast).
- **Accessibility First:** Every domain's palette designed to meet or exceed WCAG accessibility standards before teams ship. OOH domain targets 13.2:1 contrast for outdoor legibility; High Contrast reaches 21:1. Zero contrast violations shipped across 7 products; accessibility audit violations dropped to 1% over 18 months.
- **Design Efficiency:** Semantic token naming (Primary/Secondary/Success/Error vs. blue-600/blue-700) reduced designer onboarding time by 40% and design review cycles by 40%. New team members understand "what is this token for?" not "what color is this?"
- **System Maturity:** Designed component library (80+ components) shared across all 7 products; component duplication dropped from 14 variants (unintentional) to 4 (intentional). Design-to-engineering handoff time reduced by 50%.
- **Team Scale:** Single system enabled 3 design teams to work independently without creating design fracture. Figma file serves as source of truth for visuals; TypeScript tokens serve as source of truth for implementation. Bidirectional sync enforced through code review.
